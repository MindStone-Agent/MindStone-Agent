# Knowledgebases (v1)

A knowledgebase is a curated set of markdown sources with a deterministic,
citation-preserving index and a dedicated search path. Issue #13 scope. Ingest
is **extractive only** — sections and first-paragraph summaries; no model calls.

## Layout

```text
<dataDir>/knowledgebases/<id>/
  kb.json          # catalog metadata: { name, version, description }
  sources/**/*.md  # source documents (nested dirs allowed)
  index.json       # generated by ingest — do not hand-edit
```

## Ingest and index status

- `mindstone kb ingest <id>` walks `sources/`, splits each document on `##`
  headings (the pre-heading intro is its own entry), and writes `index.json`.
  Every entry preserves source metadata and a citation:
  `{ entryId, sourceId, sourcePath, sourceTitle, section, citation, summary, text, sourceMtimeMs }`
  where `citation` reads like `guides/segmentation.md § Firewall placement`.
- `mindstone kb status [id] [--json]` reports per-source state via mtime:
  `indexed` / `stale` (edited after ingest) / `unindexed` (new source) /
  `missing` (indexed but the file is gone). Re-run ingest to reconcile.
- `mindstone kb list [--json]` shows the catalog; broken `kb.json` files
  surface their error.
- `mindstone doctor` warns on broken or unindexed KBs; `mindstone status`
  reports KB counts.

## Search (citations always attached)

```bash
mindstone kb search <id> "<query>" [--limit N] [--json]
```

Lexical scoring over indexed entries (same word-overlap scorer family as local
memory recall); each hit carries its citation and summary.

## Auto Recall participation

When a KB is indexed, each source contributes one **summary + pointer**
document (memory kind `kb`) to the local/file memory recall provider used by
chat and Gateway routes — the document carries the per-section citations and
points at `mindstone kb search <id>` for full content. Full section bodies are
never injected via Auto Recall.

- Requires `memory.autoRecall: true` (same switch as the rest of Auto Recall).
- Opt out with `knowledgebases: { recall: { enabled: false } }`.
- v1 boundary: KB documents ride the local/file recall provider. When
  `memory.vectorStore` is `sqlite-vec` **and** the SQLite provider initializes,
  recall comes from that store and KB docs do not participate; embedding KB
  entries into the vector store is future scope.

## Claim status

Implemented + smoke-tested (`npm run smoke:kb`, 2026-07-02): catalog/schema
with broken-file surfacing, deterministic ingest with citation + source
metadata preservation, per-source fresh/stale/unindexed status, dedicated
search with cited hits, KB summary injection proven on a real mock-routed chat
turn (`memory_recall_injected` transcript event), and the recall opt-out. No
live-provider or embedding claims.
